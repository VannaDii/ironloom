# API المخططات

تعيش مخططات JSON الملتزم بها تحت أدلة `schemas/` المحلية للحزم.

## انجراف المخطط

تحقق من المخططات باستخدام:

```sh
cargo run -p ironloom-schemas -- --check
```

أعد توليد ملفات المخطط بعد تغييرات العقود العامة باستخدام:

```sh
cargo run -p ironloom-schemas
```

## مخططات تهيئة وقت التشغيل

- `crates/ironloom-config/schemas/runtime-config.schema.json`
- `crates/ironloom-config/schemas/stored-setup-config.schema.json`

تصف هذه الملفات تهيئة وقت التشغيل المحلولة وشكل حمولة الإعداد المشفرة.

## عقود المصنع المرشحة

توجد العقود الجديدة في وحدات `src/factory.rs` الخاصة بكل حزمة. يطبق `Validated<T>` فحوص الحقول المتداخلة والعلاقات بينها نفسها عند الإنشاء وفك الترميز، ولا تكشف الأخطاء المنظمة الأسرار. تستخدم العدادات والمراجعات سلاسل عشرية قياسية للحفاظ على دقة المتصفح. يتشارك Rust وDart الملف `fixtures/contracts/decode.json`. لا تتطلب سجلات `FactoryArtifact` الجديدة ربطًا بسلسلة Discord، ولا يتوفر دعم للتنسيقات القديمة. هذه العقود وواجهات المحولات لا تنفذ بعد المصنع أو تسجيل الدخول أو النقل الأصلي أو الاستدلال. توضح [المواصفات المشتركة](https://github.com/VannaDii/ironloom/blob/feat/shared-factory-contracts/docs/specs/ironloom-shared-contracts.md) مسؤوليات الملفات ومسارات API وحدود تهيئة المخطط الجديد والتحقق.

تضيف المراجعة سجلًا مرتبطًا بلقطة حالة وواجهة اشتراك محدودة تصل إعادة التشغيل بالأحداث الحية، وإجابات متعددة الاختيارات ونصًا حرًا، ورسائل استدلال بأدوار ومخططات الأدوات ونتائجها، ومعرفات مستقلة للخادم والبيئة مع مفاتيح حفظ الترحيل. هذه واجهات تخضع للتحقق، ولا تزال تطبيقاتها الخلفية ومحولاتها قيد الانتظار.

تحدد المراجعة نفسها واجهات معتمدة لقراءة إعدادات الفريق والنماذج والأجهزة وتعديلها، ومراجعة الدروس وتحريرها وتغيير نطاقها وحذفها ومشاركتها، والبحث المقسم إلى صفحات في المصادر، وسجلات صريحة للمسودات وذاكرة التخزين المؤقت والموارد واستعادة المحرك. تبقى البيانات المجهولة مجهولة؛ ولا يؤكد الفشل أو طلب الإلغاء توقف التنفيذ أو تحرير الحجوزات. لا تزال التطبيقات قيد الانتظار.

لم يصدر Ironloom بعد: تهيئة مخطط جديد فقط، بلا توافق مع إصدارات قديمة أو تحويل بيانات أو تعبئة لاحقة أو ملفات ترقية أو سجل ترحيل. تزال المسارات القديمة أثناء التطوير الأولي.

يحفظ `FactoryService::create_conversation` محادثة فارغة معتمدة قبل بدء الدور الأصلي، بهوية أمر دائمة ولقطة بمؤشر صفر. لا يرسل مدخلات ولا يبدأ استدلالًا؛ وتظل مدخلات المستخدم غير فارغة.

توجد عقود الخدمة والتسجيل الأصلي المشتركة الآن في `ironloom-service::factory`؛ يعتمد عليها وقت التشغيل والمحولات الأصلية بلا أسماء استيراد قديمة. تتضمن اللقطات هوية المهمة النشطة للتحكم بعد إعادة الاتصال. سجلات المشاريع والاعتمادات والاتصالات والمصادر والتنزيلات صريحة، وتحفظ ملفات النماذج حدود التوليد عبر الإعدادات.

يعيد `POST /api/v1/models/assessments` تقييمات محددة النوع للمحرك والإصدار والخلفية والأجهزة المعيارية، مع فصل الافتراضات وملاءمة الذاكرة والتحقق الفعلي. تبقى المعلومات الناقصة مجهولة، ولا يحمّل التقييم نموذجًا أو يشغّله.

يعرض `GET /api/v1/models/inventory` المصدر المعتمد واكتمال النقل والتحقق المستقل من البصمات والبيان وتوفر الملفات. لا يعني اكتمال البايتات تثبيتًا متحققًا؛ تحفظ البيانات الوصفية عند غياب الملفات ويمنع الاستخدام.

تُحفظ أوامر إعداد التثبيت قبل إنشاء أي مشروع. تحفظ المحادثات الفارغة اللقطة وإيصال إعادة المحاولة ذريًا بمؤشر صفر ودون حدث إرسال للعمل. يربط `DownloadProgress.repository_id` الاستئناف والإلغاء المصرح بهما بالمستودع الأصلي.

حدود التنزيل للبنية التحتية مطلوبة: `IRONLOOM_DOWNLOAD_MAX_FILE_BYTES` و`IRONLOOM_DOWNLOAD_MAX_TRANSFER_BYTES`. يجب أن تكون قيمتي بايت عشريتين موجبتين؛ لا تستبدلهما أحجام الناشر الاختيارية. يوفر Helm قيمًا صريحة قابلة للتعديل.

تستخدم قوالب التعليمات القابلة للتحرير `GET/POST /api/v1/instructions`؛ تحافظ التعديلات صراحةً على النسخ النشطة أو تختار مهام مصرحًا بها لتحديث النسخ وإقرارها. تحمل أوامر الميزانية `{conversation_id, budget}` لتحديد التدفق الدائم الصحيح.

يحمل `ServiceEvent` حدث عامل أو تحديث لقطة محادثة واحدًا فقط. يجب أن يطابق مؤشر اللقطة ومشروعها الحدث الخارجي؛ لا تحتاج تحديثات الحالة إلى هوية تنفيذ مختلقة.

يبدأ الفريق القياسي معطلًا بتعليمات قابلة للتحرير ودون اختيار نموذج ضمني. تحافظ قواعد الجاهزية الخالصة على وراثة المشروع وتسمح بالتشغيل البعيد المحدد دون GPU. ما زالت معالجات التعليمات والإعدادات الدائمة قيد التنفيذ.

ترتبط صلاحية العامل بالمهمة والمورد الفعليين، وتحافظ CAS على ملكية المشروع والمهمة. تفحص الجاهزية PostgreSQL وربط OpenFGA الفعلي بصورة مستقلة عن إعداد الفريق والنموذج. يتطلب تقدير الذاكرة المكونات الخمسة وجمعًا محميًا من التجاوز؛ تظل القيم الناقصة أو المتجاوزة مجهولة.


تتطلب صفحات السجل اتجاهًا صريحًا، وتدعم تصفية الدورة مع ترتيب زمني تصاعدي داخل الصفحة عند تسلسل الحدث المطلوب. تستخدم التطبيقات الأصلية `order=created_at` ولوحة التحكم `order=human_interaction`. تمنع تعيينات الأجهزة المحلية الفارغة أو المعطلة أو غير المتقاطعة جاهزية التنفيذ. تستخدم مسارات الإعداد والتعليمات والمحادثات خلفية المصادقة المشتركة؛ ولا يزال تركيب بيئة التشغيل الكاملة قيد التطوير.


لا تحتوي تعديلات الموارد دون أحداث على `CommandReceipt.cursor`. لا تتطلب إدارة الدروس المشتركة الوصول إلى محادثة المصدر الخاصة ولا تكشف مؤشرها. تحتفظ أوامر المحادثة بمؤشراتها الحقيقية. ترفض الإعدادات معرفات الأدوار المكررة دون إضافة اختيار دور بداية إلزامي.

تميّز صلاحيات الملفات في Linux بين الملفات الدقيقة `write_files` والأشجار الفرعية `write_directories`. تستخدم عمليات الإنشاء والتعديل والحذف والنقل أدوات ملفات أصلية؛ ولا تحصل الأوامر إلا على ربط الأدلة المصرح بها. تُرفض الروابط الصلبة في الأشجار القابلة للكتابة ويمنع seccomp إنشاء روابط جديدة. تبقى ملكية المسارات الدائمة حتى تأكيد التوقف أو التسوية، حتى بعد انتهاء الإيجار. لا يزال ربط بوابة التنفيذ الكاملة قيد العمل.

`ConversationSnapshot.pause_requested`: تشير `null` إلى عدم وجود مهمة نشطة؛ و`false` إلى عدم وجود طلب إيقاف مؤقت معلّق؛ و`true` إلى انتظار تأكيد التوقف عند حد آمن.

تضيف الإعدادات `endpoints` لمعرّف المزوّد وعنوان API واللهجة والفوترة ودعم البث والأدوات والاستخدام ومستويات التفكير، و`source_accounts` للمضيف مع اختيار صريح للوصول المجهول أو مرجع اعتماد. يستخدم كلاهما `/api/v1/configuration` ويرثان حسب النطاق؛ تستبدل القائمة المقدمة وحدها، وتفرغها القائمة الفارغة. ترفض عناوين المزوّد بيانات الاعتماد المضمنة والاستعلامات والأجزاء وHTTP غير المحلي. يمنع غياب المزوّد أو تعارض الفوترة أو مستوى التفكير غير المدعوم جاهزية الملف البعيد دون اختبار استدلال. يحتفظ التنزيل باختيار حساب المصدر بصورة خاصة؛ لا يزال ربط الاستدعاءات الخلفية قيد العمل.

يتطلب تغيير وجهة اعتماد فعلية إذن `ReplaceCredential`، بما في ذلك ملفات المشاريع الموروثة المتأثرة بتغيير إعدادات التثبيت. يستخدم التنفيذ العادي `UseCredential`؛ ولا يسمح إذن الاستخدام وحده بإرسال سر مشترك إلى عنوان مزوّد أو مضيف مصدر آخر.

تحفظ الملفات المحلية `local_binding`: معرّف مخزون ثابت `inventory_id` وملفات أوزان نسبية محددة `weights` ومحلّل رموز أو قالب اختياري وإعدادات `options: EngineLoadOptions`. يمنع غياب الربط الجاهزية ولا يُختار أول ملف أو نموذج بديل. يختار `ModelFilesQuery` معرّف مخزون أو مضيفًا ومستودعًا ومراجعة كاملة بصفحات محدودة. لا يزال ربط `GET /api/v1/models/files` قيد التنفيذ؛ تقتصر النتيجة العامة على المسارات والأحجام الاختيارية وSHA-256 ومصدر التحقق دون عناوين التنزيل. تُختار أوزان أرشيف Kaggle من المخزون المستخرج.

تُحفظ مواقع الدورات ونتائجها عند مؤشرات أحداث الخدمة الفعلية. يدعم التخزين الاتجاهين ونقاط الارتكاز العكسية الشاملة وقراءة معرّفات عناصر محددة بترتيبها المخزن؛ وتُرفض النقاط المفقودة أو الأجنبية أو المستقبلية. تُثبت علاقة المهمة بالمشروع قبل إعادة نتيجة الإدخال أو إعادة المحاولة، مع الاحتفاظ بنية الاسترداد عند الفشل. تقبل جاهزية مفاتيح API الوضع غير المتدفق، بينما يتطلب حساب الاستدلال المؤهل البث. لا يزال ربط الاستدعاءات الأصلية معلقًا.
